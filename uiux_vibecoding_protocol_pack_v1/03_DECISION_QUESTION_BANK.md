# 03_DECISION_QUESTION_BANK: 発火条件つき質問集

## 1. 質問運用原則
質問はUI上の割り込みであり、ユーザーの作業を止める。したがって、網羅的に全部聞くのではなく、設計に大きく影響するものだけをタイミングごとに聞く。各質問には「選択肢」「なぜ聞くか」「未回答時の既定値」を付ける。

## 2. 初回ゲート質問: 最大5個
|質問|選択肢|なぜ聞くか|未回答時|
|---|---|---|---|
|主対象端末はどれか|PC / タブレット / スマホ / 全対応|密度、ターゲットサイズ、ナビ構造が変わる|PC|
|画面種別はどれに近いか|業務管理 / 制作エディタ / 一般SaaS / フォーム / ダッシュボード|table、panel、card、formの優先度が変わる|業務管理/編集|
|最優先する体験はどれか|常用効率 / 初見理解 / 見た目 / モバイル操作|質問量、説明量、密度を決める|常用効率|
|主データの見せ方はどれか|table / list / card / canvas / form|画面骨格を決める|table/list|
|危険操作はあるか|ない / 削除 / 初期化 / 上書き / 一括変更|確認導線と配置を決める|ある前提で隔離|

## 3. レイアウト質問: モック前に必要な場合だけ
|質問|選択肢|発火条件|未回答時|
|---|---|---|---|
|ナビゲーションはどこに置くか|左sidebar / 上tabs / command palette / 不要|複数カテゴリやファイルがある|左sidebar|
|詳細表示はどこに置くか|右panel / modal / inline expansion / 別画面|行や項目の詳細編集がある|右panel|
|主操作はどこに置くか|右上 / 下部固定 / 文脈付近 / toolbar内|保存・実行・追加などがある|右上または文脈付近|
|画面は何面構成か|single / two-pane / three-pane|一覧と詳細を同時に見る必要がある|two-pane|
|モーダルを許容するか|許容 / 短時間操作のみ / 原則禁止|編集や設定が複雑|短時間操作のみ|

## 4. ラベル・アイコン質問: ブレそうな時だけ
|質問|選択肢|発火条件|未回答時|
|---|---|---|---|
|アイコンのみ操作を許すか|かなり許可 / 補助操作のみ / 原則禁止|ツールバーや行内操作が多い|補助操作のみ|
|ボタン文言はどの粒度か|短語 / icon+短語 / 説明文|ユーザーが初見説明を強く求める|短語|
|展開/折畳の表現|chevron / 「展開」ラベル / disclosure row|折畳みセクションが多い|chevron|
|tooltipを使うか|積極利用 / iconのみ補助 / 使わない|省スペース化が必要|iconのみ補助|

## 5. データ表示質問
|質問|選択肢|発火条件|未回答時|
|---|---|---|---|
|一覧は比較が重要か|重要 / 重要でない / 部分的|tableとcardの選択に影響|重要|
|行内編集は必要か|必要 / 不要 / 一部だけ|table設計に影響|一部だけ|
|一括操作はあるか|ない / 選択行に対して / 全体に対して|toolbarとselection barが必要|選択行に対して|
|ソート/フィルタは必要か|両方 / フィルタのみ / ソートのみ / 不要|header設計に影響|両方|

## 6. 危険操作質問
|質問|選択肢|発火条件|未回答時|
|---|---|---|---|
|削除は復元可能か|可能 / 不可能 / 未定|確認の強さを決める|不可能寄りに扱う|
|危険操作の配置|行内 / overflow / danger zone / 管理画面|削除・初期化がある|overflowまたはdanger zone|
|確認方法|confirm dialog / typed confirmation / undo toast / 二段階|復元不能・一括操作がある|confirm dialog|

## 7. 詳細質問は後回し
角丸、色味、影、余白感、アイコンセット、アニメーション速度などは、初回実装を止める質問にしない。`ui_config.json` やdesign tokenで後から変更する。

## 8. 質問出力フォーマット
```txt
確認したい点は最大5つです。未回答の場合は既定値で進めます。
1. [質問] 選択肢: A / B / C。理由: ...。未回答時: ...。
```
